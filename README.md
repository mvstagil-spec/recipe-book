# Кулинарная книга — подбор рецептов по ингредиентам

Это веб-приложение помогает находить рецепты по имеющимся продуктам и просматривать блюда выбранной категории, когда пользователь ещё не решил, что приготовить. Проект разработан на Python / Flask с использованием PostgreSQL и ориентирован на удобный подбор рецептов для завтрака, обеда и ужина.

Пользователь выбирает категорию «Завтрак», «Обед» или «Ужин» и вводит названия продуктов через запятую — без граммов и количества. Для просмотра полного каталога выбранной категории предусмотрена отдельная кнопка «Показать все рецепты». Карточки содержат фотографии, состав на две порции, ориентировочное время и инструкции.

## Функциональные возможности

- **Поиск по любому введённому ингредиенту (логическое «ИЛИ»).** При вводе `бекон, молоко` отображаются рецепты выбранной категории, в которых есть **бекон или молоко**. Наличие сразу обоих продуктов в одном блюде не требуется. Рецепты с большим числом совпадений показываются выше.
- **Категории блюд.** «Завтрак», «Обед», «Ужин». Выбранная категория применяется и к поиску, и к просмотру всех рецептов.
- **Режим «Все рецепты».** При обычном поиске показывает рецепты выбранной категории, совпавшие хотя бы с одним введённым продуктом. Другие необходимые ингредиенты могут отсутствовать.
- **Режим «Без покупок».** Отбирает рецепты, для которых доступны все небазовые ингредиенты; наличие определяется по названиям введённых продуктов. Базовые продукты учитываются автоматически.
- **Кнопка «Показать все рецепты».** Независимо от содержимого поисковой строки открывает полный перечень блюд **только выбранной категории**. Это отдельное действие, отличное от режима поиска «Все рецепты».
- **Распознавание названий.** Поиск учитывает регистр, `е/ё`, лишние пробелы и предусмотренные справочником синонимы (например, «яйца» / «яйцо»).
- **Базовые ингредиенты.** Соль, масло и некоторые специи считаются имеющимися дома согласно признаку `is_staple` в базе данных.
- **Карточки рецептов.** Название блюда, фотография (при наличии), ориентировочное время приготовления, состав с примерными количествами **на две порции** и инструкция.
- **Цветовая подсветка ингредиентов.** Доступные продукты выделяются визуально; отдельный список «Не хватает» и счётчик вида «Есть 1 из 2» не используются.
- **Адаптивный интерфейс.** Страница рассчитана в том числе на небольшие экраны.

> **Важно:** пользователь указывает **только названия продуктов**. Значения в граммах, миллилитрах и штуках служат справочной информацией рецепта. Режим «Без покупок» не проверяет фактический объём домашних запасов.

## Модель данных

Используется реляционная база PostgreSQL. Основные таблицы:

| Таблица | Содержание |
|---|---|
| `categories` | Категории: завтрак, обед, ужин |
| `recipes` | Название, категория, инструкция, `cooking_time` |
| `ingredients` | Ингредиенты, `canonical_name` и признак базового продукта `is_staple` |
| `recipe_ingredients` | Связь «рецепт — ингредиент», `quantity`, `unit` |
| `ingredient_aliases` | Альтернативные названия и соответствующие канонические формы |

Связь рецептов и ингредиентов — **многие ко многим**, реализована через `recipe_ingredients`. В исходном наборе предусмотрено **92 рецепта**.

### Принцип подбора рецептов

1. Пользователь выбирает категорию («Завтрак», «Обед» или «Ужин»).
2. При обычном поиске вводит названия продуктов через запятую, **без количества**.
3. Приложение нормализует названия (регистр, `ё/е`, пробелы) и сопоставляет с каноническими названиями и синонимами в базе.
4. В режиме «Все рецепты» в выдачу попадают только блюда выбранной категории, содержащие **хотя бы один** введённый продукт. Рецепты сортируются по числу совпадений.
5. В режиме «Без покупок» дополнительно проверяется, что все небазовые ингредиенты рецепта доступны. Продукты с `is_staple = TRUE` считаются имеющимися.
6. При нажатии «Показать все рецепты» поиск по введённым продуктам не применяется: отображается полный список рецептов выбранной категории.
7. Для каждого результата формируется карточка с названием, составом, инструкцией, ориентировочным временем и фотографией при наличии.

**Пример поиска:** категория «Завтрак», запрос `бекон, молоко`. В результатах могут быть «Яичница с беконом» (совпадает бекон), «Омлет» и «Блины» (совпадает молоко). Блюда, не содержащие ни бекона, ни молока, не показываются. При нажатии «Показать все рецепты» выводятся все 20 завтраков из исходного набора — независимо от запроса.

### Сценарии проверки

| Действие | Ожидаемый результат |
|---|---|
| Выбрать «Завтрак», ввести `бекон, молоко`, нажать «Найти» в режиме «Все рецепты» | Показываются завтраки с беконом **или** молоком; блюда без обоих продуктов исключаются |
| Ввести `яйца` вместо `яйцо` | Поиск распознаёт предусмотренную альтернативную форму названия |
| Переключиться на «Без покупок» | Остаются блюда, все небазовые ингредиенты которых доступны |
| Выбрать «Завтрак» и нажать «Показать все рецепты» | Показывается полный список завтраков независимо от введённого текста |
| Выбрать «Обед» и нажать «Показать все рецепты» | Показываются только обеденные блюда |

## Установка и запуск (Windows)

### 1. Требования

- Python 3 с `pip`;
- установленный и запущенный PostgreSQL;
- доступ к командной строке CMD или терминалу VS Code.

### 2. Получение проекта

Клонируйте репозиторий через GitHub Desktop или скачайте ZIP-архив из GitHub. Откройте терминал в папке с `app.py`.

### 3. Установка библиотек

```cmd
python -m pip install Flask psycopg2-binary python-dotenv
```

Для изоляции зависимостей рекомендуется использовать виртуальное окружение. Точные версии библиотек в данном README не зафиксированы.

### 4. Настройка подключения к PostgreSQL

В корне проекта создайте файл `.env` со следующими настройками (подставьте собственный пароль):

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_NAME=Recipe book
DB_USER=postgres
DB_PASSWORD=ваш_пароль
```

Приложение читает эти параметры через `python-dotenv`. Пароль не следует размещать в README, коде или GitHub-репозитории.

### 5. Создание и первоначальное заполнение базы данных

Создайте в PostgreSQL базу с именем `Recipe book` (или используйте другое имя и задайте его в конфигурации). В CMD из папки проекта выполните:

```cmd
chcp 65001
psql -U postgres -d "Recipe book" -X -v ON_ERROR_STOP=1 -f "recipe_book.sql"
```

### 6. Запуск веб-приложения

В терминале из корневой папки проекта выполните:

```cmd
python app.py
```

Откройте в браузере адрес `http://127.0.0.1:5000/`. Пока приложение работает, окно терминала должно оставаться открытым. Это локальный сервер разработки, не предназначенный для публикации в интернете без дополнительной настройки.

### 7. Проверка установки

В pgAdmin или `psql` можно убедиться, что данные загружены:

```sql
SELECT COUNT(*) AS recipe_count FROM recipes;
SELECT name, cooking_time FROM recipes ORDER BY id LIMIT 5;
```

Затем на открытой странице выберите «Завтрак», введите `бекон, молоко` и проверьте поиск по любому из продуктов. Переключите режим на «Без покупок», после чего нажмите «Показать все рецепты». Повторите просмотр полного списка для категорий «Обед» и «Ужин». Убедитесь, что изображения загружаются из папки `images/`.

## Работа с фотографиями

Фотографии находятся в папке `images/` рядом с `app.py`. Имена файлов сопоставляются с названиями блюд через словарь `PHOTO_FILES` в приложении. Поддерживаются распространённые форматы (`.jpg`, `.jpeg`, `.png`, `.webp` и другие, указанные в коде).

Если подходящий файл не найден, карточка рецепта остаётся доступной **без изображения**.

## Ограничения текущей версии

- Сайт является **локальным Flask-приложением**; размещение кода на GitHub само по себе не публикует работающий веб-сервис.
- Для запуска необходима работающая PostgreSQL и корректные параметры подключения.
- Количества ингредиентов и время приготовления **ориентировочные**.
- Проверяется наличие продуктов по названиям, **без контроля их фактических запасов**. При обычном поиске используется условие «хотя бы один введённый продукт», поэтому часть ингредиентов найденного блюда может отсутствовать.
- Подбор основан на правилах нормализации и справочнике синонимов; это не генеративная рекомендательная система.
- Пользовательская регистрация, личный список продуктов и автоматическое обновление рецептов через интерфейс в текущую версию не входят.

- SQL-скрипт первоначальной загрузки предназначен для создания базы с нуля, а не для безопасного обновления действующей базы. Перед повторным выполнением сохраните резервную копию: скрипт может удалять и пересоздавать таблицы.
