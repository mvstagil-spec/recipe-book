# Кулинарная книга — подбор рецептов по ингредиентам

Данное веб-приложение предназначено по введённым пользователем продуктам подбирать блюда, которые можно из них приготовить. Проект разработан на Python / Flask с использованием PostgreSQL и ориентирован на удобный подбор рецептов для завтрака, обеда и ужина.

Пользователь вводит названия продуктов через запятую, выбирает категорию и получает карточки блюд с фотографиями, составом на две порции, ориентировочным временем и описанием приготовления.

## Функциональные возможности

- **Поиск по ингредиентам.** Ввод названий через запятую, без указания массы или количества.
- **Категории блюд.** Завтрак, обед, ужин.
- **Два режима выдачи:**
  - **«Все рецепты»** — показывает рецепты выбранной категории и сортирует их по степени соответствия введённым продуктам; в выдаче могут быть блюда, для которых не хватает ингредиентов.
  - **«Без покупок»** — показывает только рецепты, для которых присутствуют все небазовые ингредиенты.
- **Нормализация названий.** Поиск учитывает регистр, `е/ё`, повторные пробелы, а также соответствия из справочника синонимов (например, формы «яйцо» и «яйца»).
- **Базовые ингредиенты.** Для поиска наличие соли, масла и части специй предполагается по умолчанию; перечень задаётся в базе данных полем `is_staple`.
- **Рецептурные карточки.** Название, фотография (при наличии файла), инструкция, ориентировочное время приготовления, список ингредиентов и приблизительные количества **на две порции**.
- **Визуальная подсветка.** Совпадающие и базовые ингредиенты выделяются цветом.
- **Адаптивный интерфейс.** Страница рассчитана в том числе на узкие экраны.

> **Важно:** режим «Без покупок» проверяет **наличие названий ингредиентов**, а не достаточность их количества. Граммовка отображается как справочная информация для приготовления блюда.

## Модель данных

Используется реляционная база PostgreSQL. Основные таблицы:

| Таблица | Содержание |
|---|---|
| `categories` | Категории: завтрак, обед, ужин |
| `recipes` | Название, категория, инструкция, `cooking_time` |
| `ingredients` | Ингредиенты, `canonical_name` и признак базового продукта `is_staple` |
| `recipe_ingredients` | Связь «рецепт — ингредиент», `quantity`, `unit` |
| `ingredient_aliases` | Альтернативные названия и соответствующие канонические формы |

Связь рецептов и ингредиентов — **многие ко многим**, реализована через `recipe_ingredients`. В исходном наборе предусмотрено **92 рецепта**.

### Принцип подбора рецептов

1. Пользователь выбирает категорию и вводит продукты через запятую.
2. Введённые названия приводятся к единому виду: нижний регистр, замена `ё` на `е`, удаление лишних пробелов.
3. По справочнику `ingredient_aliases` и полю `canonical_name` определяются сопоставимые названия продуктов.
4. Для каждого рецепта проверяется присутствие его небазовых ингредиентов во введённом списке. Базовые ингредиенты (`is_staple = TRUE`) считаются доступными.
5. В режиме «Без покупок» рецепты с отсутствующими небазовыми ингредиентами исключаются. В режиме «Все рецепты» рецепты сортируются по степени соответствия.
6. Для подходящих карточек формируется HTML со списком ингредиентов, изображением (если найдено), временем и инструкцией.

**Пример:** запрос `яйца, молоко` распознаёт альтернативную форму «яйца» как «яйцо». Время и количество ингредиентов берутся из базы, но пользователь вводит **только названия**.

## Установка и запуск (Windows)

### 1. Требования

- Python 3 с `pip`;
- установленный и запущенный PostgreSQL;
- доступ к командной строке CMD или терминалу VS Code.

### 2. Получение проекта

Клонируйте репозиторий через GitHub Desktop или скачайте ZIP-архив из GitHub. Откройте терминал в папке с `app.py`.

### 3. Установка библиотек

```cmd
python -m pip install Flask psycopg2-binary python-dotenv
```

Для изоляции зависимостей рекомендуется использовать виртуальное окружение. Точные версии библиотек в данном README не зафиксированы.

### 4. Настройка подключения к PostgreSQL

В корне проекта создайте файл `.env` со следующими настройками (подставьте собственный пароль):

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_NAME=Recipe book
DB_USER=postgres
DB_PASSWORD=ваш_пароль
```

Приложение читает эти параметры через `python-dotenv`. Пароль не следует размещать в README, коде или GitHub-репозитории.

### 5. Создание и первоначальное заполнение базы данных

Создайте в PostgreSQL базу с именем `Recipe book` (или используйте другое имя и задайте его в конфигурации). В CMD из папки проекта выполните:

```cmd
chcp 65001
psql -U postgres -d "Recipe book" -X -v ON_ERROR_STOP=1 -f "recipe_book.sql"
```

> **Внимание:** `recipe_book.sql` содержит `DROP TABLE`. Повторное выполнение удалит и пересоздаст таблицы. Если база уже используется или данные изменялись вручную, предварительно сделайте резервную копию.

### 6. Запуск веб-приложения

В терминале из корневой папки проекта выполните:

```cmd
python app.py
```

Откройте в браузере адрес `http://127.0.0.1:5000/`. Пока приложение работает, окно терминала должно оставаться открытым; для остановки нажмите `Ctrl+C`. Это локальный сервер разработки, не предназначенный для публикации в интернете без дополнительной настройки.

### 7. Проверка установки

В pgAdmin или `psql` можно убедиться, что данные загружены:

```sql
SELECT COUNT(*) AS recipe_count FROM recipes;
SELECT name, cooking_time FROM recipes ORDER BY id LIMIT 5;
```

Затем на открытой странице выберите «Завтрак», введите `яйцо, молоко, сыр` и проверьте переключение между «Все рецепты» и «Без покупок». При необходимости проверьте, что фотографии загружаются из папки `images/`.

## Работа с фотографиями

Фотографии находятся в папке `images/` рядом с `app.py`. Имена файлов сопоставляются с названиями блюд через словарь `PHOTO_FILES` в приложении. Поддерживаются распространённые форматы (`.jpg`, `.jpeg`, `.png`, `.webp` и другие, указанные в коде).

Если подходящий файл не найден, карточка рецепта остаётся доступной **без изображения**. Поскольку часть имён файлов записана транслитерацией, при добавлении новых фотографий нужно проверить соответствие в `PHOTO_FILES`. Для изображений, взятых из сторонних источников, необходимо соблюдать условия лицензии и указания авторства.

## Ограничения текущей версии

- Сайт является **локальным Flask-приложением**; размещение кода на GitHub само по себе не публикует работающий веб-сервис.
- Для запуска необходима работающая PostgreSQL и корректные параметры подключения.
- Количества ингредиентов и время приготовления **ориентировочные** и могут требовать кулинарной проверки.
- Проверяется наличие продуктов по названиям, **без контроля их фактических запасов**.
- Подбор основан на правилах нормализации и справочнике синонимов; это не генеративная рекомендательная система.
- Пользовательская регистрация, личный список продуктов и автоматическое обновление рецептов через интерфейс в текущую версию не входят.

## Безопасность и воспроизводимость

- Параметры доступа к базе задаются через переменные окружения; `.env` должен оставаться вне Git.
- SQL-скрипт первоначальной загрузки предназначен для создания базы с нуля, а не для безопасного обновления действующей базы.
- Для повторяемой установки можно дополнительно зафиксировать версии пакетов в `requirements.txt` и добавить автоматические тесты. Это планируемое улучшение, а не заявленная реализованная функция.

## Авторство и материалы

Проект выполнен в учебных целях. При использовании фотографий из сторонних источников необходимо соблюдать лицензию каждого изображения и указывать авторов там, где это требуется. Сведения об авторе и учебной организации могут быть добавлены владельцем репозитория.
